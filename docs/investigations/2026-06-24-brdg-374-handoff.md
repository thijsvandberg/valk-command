## What REMAINS — "B volledig" (the user explicitly chose full dispatch + optimism unification)

Goal: one shared dispatch so adding an action is implemented once; each surface's optimistic display
flows through the adapter (do NOT force one optimism model). **The three surfaces use different
optimism** and that's by design:
- **Board:** global `pendingTicketEdits` / `pendingSprintMoves` overlay (applied only by the board's
  row builder + `ticket-cache.ts` + `TicketMetaContent`) + `saveTicketMetadata` + local `readinessMap`/
  `poStatuses`. (`registerPendingEdit`/`confirmPendingEdit`/`clearPendingEdit`, `registerPendingMove`…)
- **Inbox** (`src/app/(app)/inbox/useInboxRowActions.ts` + `page.tsx`): `rowToTicket` + `localMoves`
  overlay; write-through (`tickets.updateMetadata`, `jira.*`); flag/readiness don't reflect state.
- **Epic** (`src/components/ticket-detail/EpicChildrenSection.tsx`): inline `runBulk` + `onChildOptimistic`
  callback + `localMoves`/`localMetrics`.

### Recommended approach (incremental, keep tree green at every commit)
1. **Extend `RowActionsAdapter` with an optimism protocol** the bulk handlers call instead of touching
   the overlay directly: e.g. `beginEdit(key, field, value)`, `confirmEdit(key, field)`,
   `revertEdit(key, field)`, plus the existing `commitBulkMove`. Board adapter wires these to
   `registerPendingEdit`/`confirmPendingEdit`/`clearPendingEdit` (+ `saveTicketMetadata` where the board
   does today); inbox adapter → its write-through + `localMoves`; epic adapter → `onChildOptimistic` +
   local maps.
2. **Build `useRowActions(adapter, { sprints, pinnedSprintIds, backlogTargetName, showToast, capabilities })`**
   — owns (a) the generic **bulk dispatch** (status/readiness/epic/move/quick-move/assignee/labels/flag/
   review/generate) calling the shared APIs (`jira.moveSprint`, `tickets.toggleFlag`, `apiFetch`…) +
   adapter optimism, and (b) the **glue** currently triplicated: `rowMenu` state + `handleRowContextMenu`
   (targets = selection-if-in-it-else-single), `quickMovesFor` + `handleQuickMove` (+ create-sprint
   signal), `computeFlagState`, refine/review/generate orchestration, mark-as-read. Returns ready-made
   props for `<TicketActionMenuContent>` / `<BulkActionBar>` + modal signals the host renders.
   - Board glue lives in `SprintBoard.tsx` ~lines 636–764 (rowMenu/handleRowContextMenu, quickMovesFor,
     handleQuickMove, computeFlagState, openRefine, handleBulkReviewStory, handleBulkGenerateSubtasks).
     Keep board-only bits in the host: `handleRankToEdge` (rank), `handleBulkRefresh`,
     `handleCopyToClipboard`, `handleExportForStakeholders`, create-sprint flow, flag-reason dialog.
   - Keep `useTicketActions` for the board's **per-row side-panel** handlers (poStatus/storyPoints/
     readiness single, `syncFromApiTickets`) — those are board-specific.
3. **Migrate per-surface, verify each:** board → inbox → epic.
   - **Inbox:** replace `useInboxRowActions` with `useRowActions` + an inbox adapter. **Move
     `useInboxRowActions.ts` to a `deleted/` folder (do NOT hard-delete — user rule).** Re-home
     `useInboxRowActions.test.tsx` onto `useRowActions`; keep `inbox/page.test.tsx` green.
   - **Epic:** remove inline `runBulk` + bulk handlers; use `useRowActions` + epic adapter. Keep DnD
